# Agent Note: AGENTS.md 版本与项目模板管理

Status: implemented

## Problem

用户需要保存多份全局指令，手动选择一份应用；项目指令从模板生成后独立定制，不能通过链接或模板更新覆盖项目修改。Skills 的共享链接语义不适用于项目指令。

Pi 1.1.0 会累加 agent 目录和启动目录祖先链的 context files。同目录按 AGENTS.override.md、AGENTS.md、AGENTS.MD、CLAUDE.md、CLAUDE.MD 选择首个可读取文件。项目指令不需要项目信任。单选只约束全局版本库，不意味着整个会话只加载一份指令。

## Decision

AGENTS 使用独立 Tab，管理全局命名版本、项目模板和真实项目文件。全局和项目都通过复制部署，不建链接。保存库内容不等于应用版本；模板变化永不自动传播到项目。该决定来自用户批准的设计，首版不增加模板引擎、自动同步或 Pi 扩展。

### 存储和状态

- 库内容为 `~/PiSwitch/agents/global/<UUID>.md` 和 `templates/<UUID>.md`，显示名不参与路径构造。
- `~/PiSwitch/agents-state.json` 格式版本为 1，保存版本、模板、项目、当前全局版本及最近应用指纹、模板来源快照和备份指纹／原文件权限。
- 实际全局文件为 `~/.pi/agent/AGENTS.md`，项目文件为 `<项目>/AGENTS.md`。首版与 Models、Skills 一样不自动跟随终端的自定义 agent 目录。
- 每个对象一份滚动备份位于 `agents/backups/<key>/content.md`；库内容、项目和实际全局分别备份。操作快照位于 `agents/staging/<UUID>/`。
- 项目通过文件夹选择登记，也可选择 Skills 已登记路径。不迁移或联动 `skills-state.json`；相同目录的软链接或文件身份别名不会重复登记。
- 初始目录规范化使用真实存在的祖先路径，兼容 macOS `/var` 和 `/private/var`；加载后出现的目录链接拒绝跟随。
- 启动只读取。损坏、格式不支持或关系无效的状态不重置为空记录。来源名称快照在模板删除后保留；移除项目只删登记，不删除项目文件或自动清理旧备份。

### 保存、部署与保护

编辑器支持名称和 UTF-8 内容。导入保持字节；只改名称时也复用原始内容，保留 BOM 和换行。文件限制为 2 MiB，拒绝 NUL 和无效 UTF-8，不解析 frontmatter 或添加正文元数据。

导入现有全局只复制内容并记录来源，原文件身份和字节不变。应用全局经左右内容对照确认后执行，影响使用该 agent 目录的所有项目。全局内容偏离最近应用指纹时，提供另存当前内容为版本、明确备份后覆盖、取消；不自动回写原版本。解除管理保留文件，不把删除等同于禁用指令。正在关联的全局版本不能删除。

项目模板生成普通文件。已有文件默认编辑，模板覆盖使用明确的替换确认。普通新建项目保存也提示 CLAUDE 加载来源变化。override 遮蔽时拒绝全局应用及模板部署，底层文件仍可明确编辑；界面标注保存不代表选用。恢复实际全局备份会解除版本关联，库版本恢复则只改变库内容。

`AgentsStore` actor 的同步操作段串行执行。写前核对内容、设备／inode、纳秒级修改和变更时间、权限；打开文件使用 O_NOFOLLOW，读取有大小限制，并检查读取期间及路径身份变化。链接、硬链接、特殊文件、特殊权限、所有权／组不匹配、扩展属性、ACL 和特殊标志明确拒绝，不通过 rename 丢弃这些元数据。

新全局和库文件使用 0600，新项目文件使用 0644；已有普通文件保持原权限。`ConfigStore.secureWrite` 增加内部可选权限参数，默认仍为 0600，使用 fchmod 在 rename 前完成权限设置。原模型和 Skills 调用保持默认参数，其配置格式、链接和权限语义不变。

写入顺序为保存旧目标、旧备份和旧状态快照 → 核对并写备份 → 再检查目标、来源和状态 → 同目录安全替换 → 保存状态 → 清理本操作快照。正常失败尝试恢复目标和旧备份；仅当文件仍是本次写入的身份和内容才恢复，不覆盖新出现的外部修改。恢复失败或替换后无法安全核对时保留材料并报告路径。成功但清理失败明确报告，未知暂存只提示人工检查，不自动删除或恢复。

备份指纹或限制权限变化会阻止写入。恢复也备份当前内容并旋转最近旧内容。项目目录消失时不重新创建，更不把登记记录当作实际文件存在的证明。

### 界面与接入

未选中对象时也必须能浏览和选择版本，不能用自动选择或应用掩盖空视口。当前 [B 卡片界面](2026-10-10-management-card-ui.md) 使用 100 点高的横向卡片视口及下方编辑器，替代旧 `HSplitView` 列表；全局版本、模板和项目沿用同一结构。旧分栏曾把未选中时的列表压到 0 点，状态栏仍能显示已应用版本，所以回归要检查实际视口，而非仅检查辅助功能树。保存、导入和存储保护不变。

`AgentsModel` 独立于模型配置加载失败；`AgentsView` 提供全局版本、项目模板、项目文件分区，左右内容确认和加载链预测。Core 不依赖 UI。新增代码位于 `Sources/PiSwitchCore/Agents/`、`App/AgentsModel.swift`、`Views/AgentsView.swift`，没有新增依赖或改变最低系统版本。

草稿保护覆盖对象、分区和顶层 Tab 切换以及窗口关闭与退出。保存并继续等待写入成功；失败保留草稿。忙状态阻止重入和中途关闭。缺失项目仍能移除登记，不需要读取或删除项目文件。

`AppNavigation` 共享当前页面并路由菜单保存：模型页面保留原保存逻辑，AGENTS 页面只保存编辑对象，Skills 页面无文档保存动作。⌘R 同样按页面执行本地重载，不执行全局应用。复用 `WindowCloseGuard` 闭包接口，不增加新窗口守卫。

加载链只沿所选启动目录的祖先检查固定候选，不递归扫描仓库或主目录。显示普通目录规则，并明确未处理嵌套 linked worktree 去重。App 不冒充运行中的 Pi 会话，也不自动执行 /reload。

## Alternatives considered

- **全局软链接、项目复制**：全局编辑能直接生效且内容只存一份；但复制能统一冲突和备份语义，避免未经确认的库编辑改变所有项目，所以两者都复制。
- **项目与模板三方合并**：能传播模板修复；但用户需要项目独立演化，自动合并引入冲突系统，首版不做。
- **使用 AGENTS.override.md 部署**：Pi 原生支持且可保留原文件；但会隐藏项目原文件，又不能屏蔽全局，不作为管理机制。
- **抽取共享项目登记表**：能统一 Skills 与 AGENTS 增删；但需要迁移既有格式，本轮只复用路径选择，不改变 Skills 契约。
- **只让外层分栏占满剩余高度**：无需为列表指定最小高度，布局可以完全跟随窗口尺寸；但隔离窗口中仅设置分栏的弹性高度（包括 0 点下限）仍得到 0 点列表视口，所以直接给列表保留可用高度，不自动选中版本来掩盖问题。
- **复制所有属性再替换**：可以保留带扩展属性或 ACL 的文件，扩大可编辑范围；但需要处理权限继承、所有权及属性复制失败。首版明确拒绝不能完整保留的元数据；支持此类文件时必须补充故障和权限测试。

## Consequences

- 横向卡片在未选中对象时保留 100 点视口，多条记录可原生滚动；窄窗口需要横向浏览。卡片选择调用既有草稿保护，搜索隐藏当前卡片不会清空编辑器。新增界面测试仍检查滚动视口，而非仅检查辅助功能树中的对象，因为 0 点视口的隐藏行也会出现在树中。
- 全局单选和项目独立定制可以同时成立。模板修复不会自动影响老项目，需要用户自行修改或经确认替换；来源指纹只是来源，不是同步目标。
- 一份滚动备份只能恢复最近旧内容。解除管理和移除项目保留真实文件；暂存或失去登记的备份需要人工检查，不提供自动历史清理。
- 普通文件的权限保持，但带扩展属性、ACL、共享组或硬链接的文件需要先由用户处理，不能直接接管。现有限制公开在 README 和错误文案，不静默丢失属性。
- 单文件 rename 不构成多文件事务。没有断电事务日志、进程间锁或完整崩溃恢复；最后检查到替换仍有外部竞争窗口，代码注明升级条件。恢复失败不等于原内容丢失，界面会指出保留材料。
- 运行中的 Pi 需要 /reload，历史对话不自动消除旧指令。自定义启动参数、SDK loader、扩展改写和嵌套 linked worktree 不在预测保证范围。
- 文件和备份可能包含敏感指令，App 不上传、不执行正文命令、不记录全文，不修改项目 `.gitignore` 或替用户提交。
