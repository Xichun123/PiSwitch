# Agent Note: PiSwitch 应用图标

Status: implemented

## Problem

打包脚本没有复制图标，也没有设置 CFBundleIconFile，安装后的 PiSwitch.app 显示系统通用图标。

## Decision

采用深青色背景、白色 π 与橙色开关的原创图标。Resources/AppIcon.png 保留 1024 像素母图，Resources/AppIcon.icns 包含标准尺寸与 Retina 图像。ICNS 的透明边缘直接形成圆角轮廓，不依赖系统替旧式图标裁切。

打包脚本在签名前将 ICNS 复制到 Contents/Resources，通过 CFBundleIconFile 声明图标。沿用现有 shell 打包方式，不新增依赖。[DMG 发行包](../process/2026-10-04-dmg-releases.md) 的签名与发布政策保持不变；应用图标不改变 DMG 窗口布局。

## Historical audit

DMG 发行包笔记与资源打包部分重叠，保留其发布政策并互链；现有其他功能笔记不涉及应用图标，不被取代。

## Alternatives considered

- 运行时设置 applicationIconImage：能给 swift run 的 Dock 图标赋值，但无法修复 Finder 中未启动的应用图标，因此不作为本次方案。
- 使用资产目录或 Icon Composer：能提供编译资源及分层图标，但当前应用由 SwiftPM 可执行文件和 shell 脚本组装，ICNS 可以直接接入，不扩展构建工具链。

## Verification

- iconutil 成功解包 ICNS，包含标准尺寸及 @2x 图像；PNG 母图为 1024 像素，角落透明。
- bash -n 通过。以 0.0.0 为本地测试版本运行真实打包入口，DMG 通过图标、版本、部署目标、签名与 Applications 链接检查；不上传测试产物。
- 本机已安装应用的图标文件与仓库资源一致，plist 与 ad-hoc 签名检查通过。原应用备份位于 .build/icon-update-backup/PiSwitch.app。通过 NSWorkspace 导出并检查系统识别的图标，确认不是通用图标；不启动应用或读取真实配置。

## Consequences

swift run 输出不是 .app，继续使用其默认图标。已经发布的 DMG 不会自动更新；新图标需随下次发布打包。Finder 与 Dock 可能缓存旧图标，文件与签名检查不等于桌面显示验收。
