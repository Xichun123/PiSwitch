# Agent Note: Skills 与 AGENTS 的 B 方案卡片界面

Status: implemented

## Problem

Skills 的纵向列表把描述、来源、提交、启用和检查信息堆在同一行，批量按钮始终占据工具区。AGENTS 的对象列表和编辑器固定分栏，用户难以先浏览版本再编辑。用户比较三套 Figma 方案后选择 B，并确认直接实现。

## Decision

在现有 SwiftUI 页面中实现 B 的浅紫选中态、卡片、上下信息层级和上下文侧栏。Skills 使用自适应网格；AGENTS 使用横向对象卡片和下方编辑器。软件保留系统字体、SF Symbols、原生 Tab、文本编辑器和确认弹窗，不引入 Figma 预览字体或 UI 依赖。

Skills 的搜索和全部／全局生效／项目启用／未启用筛选只投影视图，不修改记录。全局生效优先于项目分类；入口异常单独标注，不把记录当作实际可加载证明。多选只操作可见条目，搜索、筛选和范围切换会清除选择；「检查全部」和「更新全部可更新项」明确覆盖整个技能库。单个、所选、全部检查与更新以及安全停止均保留。

AGENTS 搜索只过滤对象卡片，不清空当前编辑器或保存草稿。对象及分区切换继续调用 `AgentsModel.select` 和 `selectSection`，顶层 Tab、关闭和退出保护不变。保存与应用分开，外部修改、override 遮蔽、模板独立性、备份恢复、加载链和 /reload 提示继续显示。项目文件和模板沿用相同卡片结构，但不假装自动同步。

Skills 描述摘要最多两行，并为短文本预留两行高度，避免描述长度改变折叠卡片高度。完整描述放入既有「查看详情」展开区，允许选择和复制；展开后卡片可增高，相邻卡片保持顶部对齐。错误和本地修改不受摘要行数限制。

范围是两个管理页面、共用的局部视觉样式及其隔离 UI 检查；不改变 Core、存储格式、模型页、发布或安装流程。搜索和筛选不触发网络请求。

## Alternatives considered

- A 的紧凑列表与左右编辑：原生模式熟悉，同屏条目多，现有 List 选择和滚动可直接复用。但用户明确选择 B，需要卡片和横向版本浏览，不保留 A 作为最终布局。
- C 的三栏工作台：可同时展示对象、编辑器和生效详情，减少查看上下文的切换。但宽度需求高，用户选择 B，不加入第三栏或布局模式切换。
- 按 Figma 固定尺寸、打包备用字体与 SVG：最接近预览的逐像素外观。但预览字体是渲染故障的替代物，软件已有系统字体与图标；固定 1180 点宽度和 126 点高卡片会裁切真实长文本及错误信息，因此使用平台控件与自适应高度。

## Consequences

卡片先展示名称、两行说明摘要与状态，完整描述、来源和检查详情按需展开。描述长度不再改变折叠卡片高度；错误与本地修改保持完整可见，不为齐高隐藏安全提示。代价是长描述需要展开阅读，以及 AGENTS 在窄窗口需要横向浏览版本。AGENTS 长路径单行截短，但悬停、文本复制和 Finder 操作保留完整定位信息。

搜索与筛选不写入状态或触发网络，不改变共享更新和独立项目文件语义。Core、依赖、存储格式、模型页和整窗宽度约束均未改动。界面数据来源为现有模型，不固定显示「已是最新」或「磁盘一致」。明暗主题跟随系统；深色次要操作采用浅紫前景，主要操作、复选框与启用开关保留深紫底，避免白色标记在浅紫底上对比不足。

辅助功能标识放在搜索控件自身，避免外层标识覆盖内部清除按钮；Skills 卡片使用包含子控件的辅助功能分组。隔离 NSHostingView 中的按钮标题属性不稳定，因此 UI 操作按标识定位。调整测试尺寸前把窗口放在屏幕左上可用区域，避免 AppKit 按屏幕边界缩小窗口；选中对象后重新测试 820 × 600 的实际尺寸。键盘模拟需提交输入法标记文字，不能把尚未提交的文本当作搜索结果。测试只使用现有辅助功能权限，不切换全局输入法或权限设置。

截图验证的是隔离视图，不等于完整窗口合成或 VoiceOver 实测。完整键盘遍历、系统高对比度、数百条真实记录和任意长错误布局未验收；原文件安全限制继续适用。未替换已安装应用，未提交、发布或修改真实配置。
