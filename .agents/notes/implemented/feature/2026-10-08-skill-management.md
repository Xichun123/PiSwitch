# Agent Note: Skills 管理

Status: implemented

## Problem

PiSwitch 此前只有模型配置编辑。用户需要从 GitHub 仓库识别多个 skills，确认后添加，选择全局或项目级启用，并手动执行单个及批量检查、更新。

直接安装到 Pi 的全局目录会把收藏和启用混为一件事。给每个项目复制文件，又会产生多份内容与多个更新目标。用户还要求本地修改不被覆盖、每个 skill 只保留一份旧版，并明确排除自动检查及上游改名处理。

## Decision

Skills 使用独立 Tab。添加、保存、启用和更新分开执行，数据不写入 `models.json` 或 `settings.json`。模型保存、重载、草稿和未保存保护继续使用原逻辑，`⌘S` 不触发 Skills 写操作。

### 来源、发现和下载

`SkillRepository` 接受公开 GitHub 仓库首页地址，规范化末尾 `/` 和 `.git`，拒绝凭据、非 HTTPS、非 GitHub、分支或文件地址。更新跟随仓库默认分支；没有私有仓库令牌、分支设置、npm 或其他托管平台入口。

解析通过仓库元信息、默认分支提交和递归文件树固定提交，然后识别 `SKILL.md` 候选。候选显示名称、描述、来源路径和不可添加原因；默认不选中，即使只有一个候选也需要确认。用户确认后才下载所选目录的支持文件并创建正式安装目录。

下载使用固定提交，不在多文件下载途中跟随移动分支。文件字节数及 Git blob SHA 与文件树校验；可执行文件保留执行权限。仓库脚本不执行，依赖不自动安装。文件树截断、无候选、文件缺失、内容校验失败、403/429 限流或访问拒绝、404 不可访问和其他网络错误均明确报告，不把失败当成已是最新。

名称遵循小写字母、数字及单个连字符，最多 64 字符；描述为非空字符串，最多 1024 字符。Yams 6.2.2 解析 frontmatter，支持引号、多行和常见转义，拒绝重复字段及非字符串必需字段；bool 解析采用 true/false，避免把合法名称 on/off 误当布尔值。

每个 skill 最多 1,000 个文件、单文件 10 MiB、合计 50 MiB；候选最多 100 个，`SKILL.md` 最多 256 KiB。本地指纹扫描最多 2,000 个文件或目录条目。相对路径校验拒绝路径穿越、绝对路径、控制字符、文件/目录冲突及大小写路径冲突。仓库内符号链接和子模块明确拒绝，不静默遗漏或跟随外部内容。

### 统一文件库与记录

```text
~/PiSwitch/
├── skills/<skill 名称>/       # 当前完整目录
├── backups/<skill 名称>/      # files/ + record.json，唯一旧版
├── staging/<UUID>/            # 暂存、快照和轮换期间的旧备份
└── skills-state.json          # 格式版本、技能、项目和待清理操作记录

~/.pi/agent/skills/<skill 名称> # 全局软链接
<项目目录>/.pi/skills/<skill 名称> # 项目软链接
```

路径从当前用户主目录解析，不写死用户名。备份和暂存区不位于技能库或 Pi 扫描目录内。安装目录固定，正常更新不重建启用入口。

来源身份是规范化仓库和 skill 来源路径，不按名称猜测其他来源。安装记录保存 UUID、名称、描述、仓库、路径、提交、来源目录指纹、本地文件基线和启用范围。来源指纹覆盖排序后的相对文件路径、Git 模式及 blob SHA；本地 SHA256 基线覆盖目录条目、相对路径、文件内容和执行权限，两种指纹不混用。

独立状态文件格式版本为 1。读取验证路径、标识及记录关联，写前比较已加载字节基线，再复用 `ConfigStore.secureWrite` 的排他 0600 临时文件和 rename。语法或格式损坏停止写操作，不重置为空记录。存储路径被替换为外部链接时拒绝写入，不接管已有内容。

### 添加与启用保护

同一来源已添加时标记已添加，不重复安装；不同来源同名或安装目录占用时拒绝并显示来源或路径。添加后默认未启用，不自动迁移已有 skills，也不为来源不明的文件猜测更新地址。

全局启用对所有项目生效；项目页标注全局生效，不提供重复勾选。未全局启用的 skill 可以分配一个或多个项目。项目经文件夹选择器明确添加，保存规范化绝对路径，不扫描磁盘猜测项目。不提供项目屏蔽全局、覆盖全局或独立版本。

启用创建软链接，链接及记录成功后才显示成功。已托管且目标正确的入口不重复创建；实体目录、文件或外部链接占用时不覆盖、不搬走。取消启用只删除预期托管链接，不删除技能库内容；链接已被外部修改则停止删除并报告目标。

切换为全局前列出将移除的项目入口并确认，链接调整或记录失败尝试恢复原入口。项目目录失效、入口或 `SKILL.md` 缺失时，检查显示入口异常，不能把记录存在等同于实际可加载。

启用前扫描默认全局 `.pi/agent/skills`、用户 `.agents/skills`、目标项目 `.pi/skills` 与 `.agents/skills` 的名称冲突；全局启用还检查已登记项目。扫描跟随目录软链接、避开循环，遇到 skill 根不继续扫描其支持文件，符合当前 Pi 的根目录停止规则。它不枚举所有 Pi 包、自定义路径或项目祖先 `.agents/skills`。

### 手动检查与更新

单个、多选、全部检查均由按钮触发，没有启动或定时检查。同一次批量操作按仓库复用固定提交及文件树；某仓库请求失败在本次操作内复用错误，避免反复请求。检查比较 skill 的来源目录指纹，无关仓库提交不产生该 skill 的更新提示。

本地新增、删除、内容或执行权限变化独立展示，已是最新也可以有本地修改。更新默认跳过并列出变化；不自动合并、忽略缓存或强制覆盖。下载后、备份后及实际替换前再次核对本地基线。

更新顺序是：暂存新版并校验 → 准备当前文件与对应安装记录的快照 → 再检查本地修改及旧备份 → 移动当前版 → 安装新版 → 轮换备份 → 保存新版状态 → 清理更旧备份及暂存目录。

v1 更新到 v2 后保存 v1；v2 成功更新到 v3 后保存 v2，自动删除 v1。不能先删除原有 v1 再尝试第二次更新。下载、校验或备份失败保留当前版；替换或记录写入失败尝试恢复 v2 及原 v1 备份。恢复失败明确报告保留的操作目录，不假装已恢复。

写状态成功前允许临时快照；写成功后待清理 UUID 记入状态。清理失败显示「操作成功，清理未完成」，后续本地读取或操作重试，不作为额外历史备份功能。旧备份校验失败时不覆盖用户修改过的备份。未在清理记录中的未知暂存目录只提示检查，不自动删除。

批量任务首版串行，单项失败或跳过不阻止其他项，不回滚已经成功的项。`SkillsModel` 的忙状态阻止任务重入；`SkillStore` actor 的同步写段不会被取消打断。「安全停止」取消网络或后续项，正在执行的文件写段仍完成或恢复。任务期间关闭与退出先检查 Skills 忙状态，再执行原模型草稿保护。

不处理上游改名，不加入改名检测、目录迁移、链接改名或通知。安装目录和启用入口仍保持原值。没有历史备份界面、一键恢复界面或覆盖全部冲突授权；正常失败恢复属于存储逻辑。

### 实现落点

- `Sources/PiSwitchCore/Skills/SkillTypes.swift`：来源、frontmatter、安全校验、指纹和记录类型。
- `Sources/PiSwitchCore/Skills/SkillRepository.swift`：复用 `HTTPFetcher` 获取固定快照及文件，未修改原发现请求逻辑。
- `Sources/PiSwitchCore/Skills/SkillStore.swift`：安装、更新、项目、链接、失败恢复及清理；Core 不依赖 UI 框架。
- `Sources/PiSwitch/App/SkillsModel.swift`：主线程可观察状态，网络与磁盘操作委托异步接口，结果逐项展示。
- `Views/SkillsView.swift`、`Views/AddSkillsSheet.swift`、`ContentView.swift` 和 `PiSwitchApp.swift`：独立 Tab、添加确认、全局/项目开关及关闭、退出守卫。
- `AppModel` 默认行为不变，构造器可注入已有 `ConfigStore`，供完整界面验收使用虚构的损坏模型配置，避免读取用户文件。
- `Package.swift` 和 `Package.resolved`：唯一新增依赖 Yams，哈希使用 Apple CryptoKit。现有模型 UI 验收脚本链接新增包对象；控件增加稳定辅助功能标识，不改变输入绑定。

## Alternatives considered

- **直接安装到全局或项目目录**：Pi 能直接发现，存储和启用合为一步，管理记录最少。但违背独立技能库要求，并导致各项目持有多份更新目标，因此统一存储并用链接启用。
- **通过 settings.json 的 skills 路径列表启用**：Pi 原生支持，能避免链接文件。但需要同时编辑用户与多个项目配置、保留未知字段及处理配置冲突。已验证当前 Pi 可通过目录软链接发现 skill，所以使用扫描目录，不扩大配置编辑范围。
- **手写 frontmatter 子集解析**：无需依赖，简单格式只需少量代码。但任意仓库可能使用引号、多行、转义及重复字段，自行扩展形成另一个解析器，因此使用 Yams。
- **保留所有历史备份**：恢复选择最多，也无需清理更旧版本。但用户明确要求一份旧版，所以成功后轮换，失败期间保留恢复所需快照。
- **更新时处理上游改名并通知**：能同步显示名称和入口，减少用户手工操作。但用户最终决定不考虑此情况，本实现不加入该分支，也不把它塞进普通更新流程。

## Consequences

- 统一更新只写一份文件，也同时影响所有已启用项目。正在运行的 Pi 需要 `/reload`；项目加载仍受 Pi 项目信任约束，App 不授予信任。跨机器使用项目需要重新安装及建链接。
- 一份滚动备份限制历史版本数量，但只能恢复最近旧版；清理失败可能临时留下额外快照，界面报告并重试。
- 正常失败恢复经过故障注入；没有完整崩溃事务日志、进程间锁或断电保证。外部程序在最后检查后的写入竞争仍可能发生，不能称为完整原子更新。添加崩溃恢复前不得自动删除未知暂存内容。
- 名称冲突检查只覆盖已扫描入口，不保证覆盖所有包或自定义路径。上游改名不处理，后续 Pi 命令和冲突行为可能变化，不承诺迁移引用。
- 公开接口存在限流及仓库大小限制；首版不引入令牌或 Git 依赖。仓库外依赖不下载，不主动处理 Git LFS 内容。
- 第三方 skill 的指令与脚本不因内容校验而变安全。下载时不执行脚本，启用前仍需用户审查；技能库及备份可能含自定义内容，不上传遥测或写入仓库。
- CryptoKit 使当前 Skills Core 要求 Apple 平台。默认全局入口不跟随自定义 `PI_CODING_AGENT_DIR`；如需跨平台 Core 或自定义 agent 目录，应单独扩展并验证契约。
- 未替换已安装 App、打包发布 DMG、创建 Git 提交或修改真实 Pi 配置。本轮仅修改源码及文档、构建并使用隔离目录验证。
