# Agent Note: 侧栏展开的列级最小宽度

Status: implemented

## Problem

用户在安装原生侧栏动作候选版后，确认窄窗口仍有半程停住再跳至全宽的现象，横向拉宽窗口后消失。固定宽度、前台且 key 的隔离窗口录像复现：820 和 940 点时，可见边缘从约半宽停留后跳到完整宽度；1040 和 1180 点没有相同跳变。每种宽度的实际列状态切换、工具栏作用域及草稿检查都通过，说明旧检查没有覆盖这段画面。

修改前，窗口根内容固定 `.frame(minWidth: 820)` 是可复现触发条件。在窗口实际宽度仍为 820 点时，只降低根内容最小宽度至 560 或 0，跳变消失。替换表单、分栏样式、侧栏宽度范围或状态绑定没有消除跳变。保留 820 点 NSWindow 最小宽度而降低 SwiftUI 根内容最小宽度也消除了跳变，因此不应把问题简单处理成窗口必须更宽。

## Decision

把最小宽度放在需要它的内容上：模型详情列使用 590 点（原默认完整宽度 820 减去默认侧栏 230），Skills 页保留原来的 820 点。应用 Scene 的根内容仅保留最小高度，不对整个分栏的根内容再施加 820 点宽度下限。原生分栏在展开、收起及拖动侧栏宽度时计算整个窗口的最小宽度。

沿用现有原生侧栏动作、columnVisibility Binding、图标及动态按钮名称。侧栏仍可在 200–320 点间调整；不删动画、重写导航或更改数据格式。隔离检查也移除额外的根宽度下限，以测试实际产品约束。增加收起状态下最小宽度能回到 590 点的回归检查，且使用同宽度录像检查真实展开过程。

具体作用域是 Sources/PiSwitch/Views/ContentView.swift 中的 detail 和 SkillsView；Sources/PiSwitch/App/PiSwitchApp.swift 不再承担横向内容约束。默认侧栏 230 点加详情 590 点仍得到 820 点；侧栏调整到 320 点时，观察到详情加侧栏的最小宽度为 910 点，收起后返回 590 点。

## Historical audit

- [原生侧栏动作](2026-10-09-sidebar-native-animation.md) 部分重叠：保留其动作路由、Binding 同步与辅助功能名称；宽度试验证明单独改变动作不能解决窄窗口跳变。本决定补充布局约束的作用域，不把旧候选倒写为已解决问题。
- [工具栏溢出修复](2026-10-09-sidebar-toolbar-overflow.md) 部分重叠：固定按钮、移除自动 sidebarToggle、工具栏作用域及草稿保留继续适用。恢复自动按钮的试验仍有半程跳变，并重新观察到溢出指示器，不能撤销这项修复。
- [模型默认折叠](../../implemented/feature/2026-10-01-collapsible-model-details.md) 和 [Skills 管理](../../implemented/feature/2026-10-08-skill-management.md) 部分重叠：模型展开/草稿逻辑及 Skills 操作契约不变；Skills 保留其原有最小可用宽度。

## Alternatives considered

- 提高整窗最小宽度：改动最少，宽窗口已经有正常录像对照；但会禁止用户当前可用的窄窗口，不修复约束放错作用域的问题。
- 只降低整窗最小宽度：820 点窗口中的录像确实恢复连续展开，代码也只需改一个数值；但不说明各内容区所需宽度，可能允许表单或 Skills 挤到不可用，不采用。
- 根据 columnVisibility 动态设置根宽度为 590/820：保留完整展开宽度，820 点录像也没有半程跳变；但重复了分栏已掌握的列宽计算，也会让模型的列状态影响另一个 Tab。选择列自身的下限，由原生布局合并。
- 调整 balanced 样式、固定侧栏 230 点、放宽详情框架或禁用 SwiftUI 事务：保留现有导航、改动很小；在可复现的 820 点窗口中，都仍出现约 115 → 230 点的末段跳变。

## Consequences

- 默认完整窗口的最低宽度预算不变，约束不再作为一条覆盖整个分栏动画的根宽度下限。默认请求尺寸仍为 1040 × 700；高度、关闭保护、配置和草稿契约不变。
- 收起侧栏后模型页可缩窄到 590 点；展开或切到 Skills 时，系统会按内容下限扩大窗口。实验中，收起并缩窄至 590 点后展开恢复为 910 点，对应恢复的 320 点侧栏。
- Skills 的 820 点下限在其自身视图上，不再取决于模型页的列状态。模型页选中时，未选中的 Skills 页下限不参与侧栏动画。
- 590 是沿用原默认 820/230 的详情预算，不是所有未来表单都足够；添加更宽控件时应调整详情列而不是整窗根宽度。
- UI 检查明确验证 collapsed_minimum=true 的结果行，不仅依赖按钮按压或应用退出状态。新增检查在旧根宽度约束下输出 false 并使 runner 失败，修复后输出 true。
- 测试窗口建立后显式 makeKeyAndOrderFront，再激活应用，确保原生响应链在前台执行；仅在启动回调请求激活未能稳定通过前台检查。
- 录像验证限于本机 macOS 27 和当前内容。实际用户窗口仍需验收，20 ms 逻辑状态采样不是所有连续画面的保证。本地验收阶段按用户要求完成替换，没有写真实配置、提交或发布，安装版元数据为 0.2.1。发行目标为 v0.2.2，打包脚本由版本标签生成新的应用版本元数据，不修改配置格式。
